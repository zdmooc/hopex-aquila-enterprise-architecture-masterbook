# Partie III — UI, Navigation, Objects, Properties & Workspaces

Cette partie apprend à utiliser le Web Front-End HOPEX comme une **projection d’un repository gouverné**, et non comme une collection d’écrans.

## Objectifs

À la fin de cette partie, il faut savoir :

- se repérer dans un workspace par persona ;
- rechercher avant de créer ;
- ouvrir et qualifier une fiche objet ;
- lire propriétés et relations ;
- exploiter listes, filtres, matrices et diagrammes ;
- distinguer objet, représentation et vue ;
- naviguer Application → Business → Technology → Transformation ;
- préparer une impact analysis ;
- collaborer et valider sans dégrader le repository ;
- traiter current/target ;
- utiliser MayaBank comme fil rouge.

## Frontière importante

Le Store MEGA confirme le rôle du **HOPEX Web Front-End** comme portail web pour les profils EA/GRC et celui du **Core Back-End** comme moteur de logique et d’accès au repository. L’organisation précise des menus, boutons, workflows et workspaces peut varier selon version, licence, solution et configuration client.

Le masterbook enseigne donc :

```text
la logique durable du repository derrière l’UI
```

et évite de transformer une capture d’écran d’une release en vérité universelle.
