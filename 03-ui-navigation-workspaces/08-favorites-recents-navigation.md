# 08 — Favorites, Recents & Personal Productivity

## 1. Productivité personnelle sans fragmentation

Les mécanismes de favoris, historiques/récents ou raccourcis — lorsqu'ils sont disponibles dans la configuration — doivent aider l'utilisateur à revenir vers **les mêmes objets canoniques**.

Ils ne doivent pas devenir une taxonomie parallèle.

## 2. Favoris utiles

Favoriser :

- objets dont on est owner/steward ;
- vues utilisées en comité ;
- listes de revue récurrentes ;
- roadmaps suivies ;
- domaines actifs.

Éviter de favoriser 200 objets sans logique.

## 3. Dossier mental de l'architecte Paiements

```text
Core objects
- Instant Payment Capability
- Instant Payment Process
- Payment Orchestrator
- Fraud Engine
- Event Streaming Platform

Decision views
- Payment Target Architecture
- Payment Dependency Map
- Migration Roadmap

Review queues
- Applications needing review
- Critical technologies
```

## 4. Recents ≠ ownership

Un objet consulté récemment n'est pas nécessairement important. Utiliser l'historique pour reprendre le travail, pas comme liste de gouvernance.

## 5. Deep links

Quand un objet possède une URL réutilisable dans l'environnement, privilégier le lien vers l'objet ou la vue HOPEX plutôt qu'une capture d'écran dans un mail.

Cela favorise :

```text
Live repository
→ current data
→ relationships
→ context
```

## 6. Capture écran

Une capture est acceptable pour :

- un compte-rendu daté ;
- un support de comité ;
- une preuve ponctuelle.

Elle ne remplace pas l'objet vivant.

## 7. Notes personnelles

Ne pas stocker dans une propriété d'architecture des notes personnelles non gouvernées.

Séparer :

```text
Repository fact
Decision rationale
Working note
Personal reminder
```

## 8. Routine quotidienne

### Début de journée

```text
Pending reviews
→ assigned objects
→ quality alerts
→ current initiatives
```

### Avant Architecture Board

```text
Decision candidates
→ related views
→ incomplete data
→ owners
→ target impacts
```

### Après décision

```text
Update canonical objects
→ update lifecycle/relations
→ record rationale
→ verify dependent views/reports
```

## 9. Routine hebdomadaire

- objets créés récemment ;
- doublons suspects ;
- décisions sans mise à jour repository ;
- revues échues ;
- vues utilisées mais non maintenues ;
- listes personnelles devenues critiques.

## 10. Anti-patterns

- favoris comme seule navigation ;
- captures PowerPoint comme source ;
- bookmarks vers objets dupliqués ;
- notes personnelles dans Description ;
- utilisation de Recents pour prouver une responsabilité.

## 11. Lab

Définir le cockpit personnel d'un architecte MayaBank avec :

- 5 objets favoris maximum ;
- 3 vues ;
- 3 listes de revue ;
- 2 roadmaps ;
- 1 rituel hebdomadaire de qualité.

Justifier chaque entrée par une décision récurrente.
