# Partie VI — Capability Architecture

Cette partie approfondit la Capability Architecture dans HOPEX sans répéter la Partie V. Elle traite la capability comme un objet de gouvernance relié à la stratégie, aux applications, aux données, aux technologies et aux investissements.

## Ce que vous devez savoir faire après cette partie

- construire une taxonomie cohérente ;
- décider quand descendre de L1 à L2/L3 ;
- distinguer capability, process, org-unit et application ;
- évaluer importance, current maturity et target maturity ;
- produire une heatmap défendable ;
- mapper capabilities vers applications, data, technologies, org-units et initiatives ;
- détecter redondance, sous-couverture et dépendances critiques ;
- comparer plusieurs scénarios d'investissement ;
- construire une capability roadmap ;
- utiliser BIAN comme référence sans le confondre avec le modèle d'entreprise ;
- défendre une priorisation devant un Architecture/Investment Board.
